Backend · web layer

FastAPI, Starlette, Uvicorn, Pydantic

Four libraries with four distinct jobs. Each one is replaceable in theory and load-bearing in practice.

FastAPI 0.162

the API surface
  • Routers per resource: auth, scrape, automate, jobs, keys, schedules, webhooks, billing, exports, metrics, health.
  • Dependency injection: Depends() resolves the DB session, current principal, org and required scope.
  • Async endpoints: all I/O is awaited; long work is offloaded, never awaited in-request.
  • Contract generation: response_model produces the OpenAPI schema served at /docs.

Starlette 1.10

the foundation

ASGI toolkit underneath FastAPI. Used directly for the RequestContextMiddleware that accepts a safe X-Request-ID, binds it to logs, and rejects unsafe values.

Uvicorn 0.32 [standard]

the server

Runs the ASGI app on port 8000 inside the container. [standard] adds uvloop and httptools for throughput; health probes hit /health and /ready.

Pydantic v2 2.9+

the contract

Rust-backed validation and serialisation. pydantic-settings loads .env into a typed Settings object at startup, so a bad secret fails fast.

Why this combination
  • OpenAPI for free: 29 documented routes become a browsable, testable contract.
  • One validation layer: the same Pydantic models guard HTTP input and serialise output.
  • Typed settings: missing DATABASE_URL is a startup error, not a 3 a.m. surprise.

Backend · persistence

SQLAlchemy async, asyncpg, Alembic, PostgreSQL 16

PostgreSQL is the source of truth. Redis is a cache and a queue — never the record of what happened.

SQLAlchemy 2.0 (async)

AsyncSession per request, declarative models, typed select(). Relationships and constraints live in the model layer, not in ad-hoc SQL.

asyncpg 0.30

The actual PostgreSQL driver. Binary protocol, prepared statements, no psycopg overhead. URL form: postgresql+asyncpg://….

Alembic 1.14

Five versioned migrations run by the migrate compose service before the API starts. alembic current / heads are documented runbook commands.

Pooling fix that matters

Celery tasks create and destroy an event loop per job. Reusing a pooled asyncpg connection across loops caused Future attached to a different loop; workers now use NullPool and a regression test runs the reaper across two loops.

Backend · async work

Celery, Redis, Beat and croniter

The API answers in milliseconds; workers do the slow, failure-prone part with retries and a hard deadline.

Celery 5.4

worker
  • Prefork pool: isolation from crashes and blocking Selenium calls.
  • Retries: max_attempts=2 recorded on the job row.
  • Task families: jobs, reaper, reconcile, retention, schedules, webhooks, health.
  • Multiprocess metrics: prefork counters aggregated through PROMETHEUS_MULTIPROC_DIR on port 9101.

Redis 7

broker + state
  • Broker: Celery task transport with append-only persistence enabled.
  • Token bucket: atomic Lua script per key/org — no race between read and write.
  • Idempotency: Idempotency-Key replays the original job instead of double-charging.
  • Locks & counters: short-lived coordination that is safe to lose.

Beat + croniter

time
  • Beat scheduler: separate container, schedule file on a tmpfs.
  • croniter 3.0: validates cron expressions and computes the next fire time.
  • Run history: every fire creates a schedule_runs row with a terminal status.
  • Manual trigger: POST /v1/schedules/{id}/run for testing.

Failure handling, explicitly

  • Hard timeout: a job cannot run forever; it moves to timed_out.
  • Reaper: scheduled task kills orphan browser sessions and reconciles stuck rows.
  • Reconcile: compares broker and database state after a crash.
  • Retention: expires artifacts according to the plan's retention days.
  • Webhook outbox: deliveries survive a worker restart and retry with backoff.

Backend · scraping engine

httpx for speed, Selenium for truth, parsel for shape

Two execution paths behind one contract, both forced through the same validating egress proxy.

httpx 0.27

fast path
  • Async HTTP client with explicit timeouts and redirect limits.
  • Used when render_js=false; typically a fraction of a browser run.
  • Custom headers, user agent, proxy routing via the egress proxy.
  • Response status, final URL and redirect chain are recorded in the result.

Selenium 4.25

browser path
  • Remote WebDriver against standalone-chrome:4.25.0 in Selenium Grid.
  • Waits for a selector, captures screenshots and HTML.
  • Powers the automation step DSL: goto, click, type, wait, extract, screenshot.
  • Sessions are bounded and reaped; the API container never launches Chrome.

parsel 1.9

extraction
  • CSS and XPath selectors over the fetched HTML.
  • Attribute extraction, multi-match lists, named result fields.
  • Page text, links and meta tags with hard limits.
  • Result is normalised to plain JSON for storage and export.
SSRF defence in depth
  • Policy layer: scheme allow-list, port rules, private/link-local/loopback denial at request time.
  • Validating proxy: resolves DNS, checks every address, then connects to the pinned IP — not the hostname.
  • Chained upstreams: optional commercial proxies sit behind the validator, never around it.

Backend · object storage

Artifacts: boto3 over an S3-compatible API

Screenshots and HTML are too large for a database row and too useful to lose. They live in object storage, addressed by row metadata.

boto3 1.35+

Single S3 client configured by ARTIFACTS_ENDPOINT, bucket and credentials. Works against MinIO, AWS S3, or adobe/s3mock locally.

Write path

Worker uploads screenshot.png, page.html and result.json, computes SHA-256, then inserts an artifacts row with content type, size and expires_at.

Read path

GET /v1/artifacts/{id}/download authorises the caller, then redirects to a short-lived presigned URL. The browser never sees storage credentials.

Retention

Plan-dependent: 1 day on Free, 7 Starter, 30 Pro, 90 Business. The retention task deletes expired objects and rows.

Backend · security

Identity, secrets and egress are separate defences

Authentication

PyJWT 2.9

Short-lived access tokens signed HS256; claims carry user, org and role. Refresh tokens rotate and are stored hashed.

Passwords

argon2-cffi

Argon2id hashing with per-password salt. No plaintext, no reversible storage, constant-time verification.

API keys

Pepper + SHA-256

Keys are shown once. Only a hash with a server-side pepper is stored, so a database leak alone cannot replay them.

Secrets at rest

cryptography 50

Webhook signing secrets and proxy credentials are encrypted with Fernet before they reach PostgreSQL.

Authorisation

  • Roles: owner, admin, member.
  • Scopes: scrape:write, automation:write, jobs:read, schedules:write, exports:read, keys:manage, billing:manage, audit:read.
  • Enforcement: a dependency resolves the required scope before the handler runs.
  • Audit: sensitive actions append to audit_logs.

Session model

  • Access token kept in memory in the dashboard.
  • Refresh token in an httpOnly, same-site cookie.
  • Rotation on refresh; logout revokes the stored token.
  • No tokens in localStorage; the BFF keeps the browser same-origin.

Egress control

  • Private, loopback, link-local and metadata ranges denied.
  • DNS resolved and validated at connect time.
  • Validated IP pinned to close rebinding.
  • Header and byte caps; hop-by-hop headers stripped.

PII and logging: Sentry initialises with send_default_pii=False; structured logs carry identifiers, not secrets. /metrics can be disabled or protected with METRICS_TOKEN.
